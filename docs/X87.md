# x87 environment extension

`tools/x87_extension.py` and `runtime/transformers_x87.h` are project-owned
extensions to the pinned **global-register** pcrecomp model. They do not alter
the external checkout. They implement the protected-mode, 32-bit-operand-size
28-byte `FNSTENV` / `FLDENV` image. This is a bounded environment implementation,
not a complete x87 emulator or a claim that the game runs correctly.

## Integration

After making the pinned `tools.lift.lift32.Lifter` importable:

```python
from x87_extension import make_x87_lifter
ProjectLifter = make_x87_lifter(Lifter)
```

The returned class overrides `_lift_instruction`, leaving upstream integer flag
capture in `lift_instruction` intact. Another project subclass may derive from
this class. Both Capstone instructions and pcrecomp's `disasm32.Instruction`
wrapper are supported. Include `transformers_x87.h` **after** `recomp_types.h`
and before generated function bodies in every generated translation unit.

The header defines shared `TF_X87State g_tf_x87` and replaces `fp_push` / `fp_pop`.
It uses existing `g_st`, `g_st_i64`, `g_fpu_cw` and segment registers. Host state
snapshots must save the entire `g_tf_x87`, the arrays, CW and upstream depth.
The existing `g_fp_top` is a **depth**, not the hardware TOP field. Hardware TOP
is tracked independently in `g_tf_x87.top`.

The occupied count is maintained incrementally by mark/push/pop/free. Marking
an empty physical slot increments it, popping a required nonempty slot
decrements it, and freeing an already empty slot leaves it unchanged. Whole-tag
writes and environment loads still recompute it with `tf_x87_depth()`. This
avoids an eight-slot scan after every stack operation without changing values,
tag classification, physical TOP, or saved environments. The additional
`test_runtime_hotpaths.py` fixture covers all 65,536 tag words at all eight TOP
positions, including repeated frees and empty-slot stores.

## Implemented state

The 28-byte image contains CW at 0, SW at 4, the full tag word at 8, FIP at 12,
CS at 16, eleven opcode bits at 18, FDP at 20 and DS at 24. The tag fields address
physical registers. Loading changes TOP without loading register data; nonempty
tags are classified using the retained values. Reserved image bits are excluded
from conformance comparisons. These rules follow Intel's Volume 1, sections
8.1.7–8.1.10 and Figure 8-9.
[Intel SDM Volume 1](https://cdrdv2-public.intel.com/843827/253665-sdm-vol-1-dec-24.pdf)

The logical register array rotates instead of dropping the last slot during a
push/pop. Popped and initialized physical contents remain available if a later
`FLDENV` makes them visible. `FINCSTP`, `FDECSTP`, `FFREE`, `FFREEP`, `FNINIT`,
`FNCLEX`, control-word operations and persistent status reads use the same model.
Generated comparisons publish their condition bits across function boundaries.
`FXAM` handles empty tags and treats finite nonzero binary64 values as normal
extended values. Pointer tracking uses the guest instruction address and guest
operand offset, including the proper SS default and explicit segment override.

`FNSTENV` writes the original environment before setting all six exception masks.
`FLDENV` derives pending exception summary state from exception flags and masks;
the next waiting instruction checks it. `FNOP` records its instruction pointer.
[Intel SDM instruction reference](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf)

## Explicit limitations

`g_tf_x87.limitations` is initialized to `TF_X87_LIMITS` (15): binary64 register
precision, incomplete arithmetic exception flags, unapplied precision control
and incomplete rounding-mode behavior. These limitations persist even when all
environment tests pass. Existing arithmetic/transcendental implementations do
not become exact merely because CW and SW can now be saved.

Exception flags already loaded by `FLDENV` are preserved, and `FNCLEX` clears
them. Most arithmetic still does not generate hardware exception flags or exact
C1 rounding information. SNaN distinctions, unsupported 80-bit encodings and
x87 subnormals are not represented. Mixed MMX/x87 physical-register aliasing is
not modeled by the upstream separate MMX array; environment fidelity across MMX
use remains unverified. The state is shared rather than thread-local, so the
runtime must prohibit guest threads until register contexts are implemented.

A pending unmasked exception or an empty-register/stack-overflow operation
terminates with `TF_X87_FAULT` instead of pretending that guest exception or
masked stack-fault handling exists. The default fault prints a reason and calls
`abort`; a host may replace it with a nonreturning diagnostic hook. This is an
intentional unsupported-state stop, not architectural exception dispatch.

Operand-size-override 14-byte environments produce `RECOMP_TODO`. Real mode,
virtual-8086 mode, save/restore of the full 80-bit register file, precise page
fault/SEH delivery, and all unknown upstream instructions remain unsupported.
Guest memory bounds and segment register initialization remain host-runtime
responsibilities. No proprietary executable is run by the tests.

## Verification

```powershell
python -m unittest discover -s tests -p test_x87.py -v
```

On this Windows x64 host, 12 tests pass, including **248 hardware differential
cases**. The oracle saves/restores the caller's FPU state and executes only short
synthetic x87 sequences. NDK Clang independently compiles the C helpers into a
freestanding AMD64 COFF fixture. A checked test-only loader resolves its local
sections and relocations, rejecting external symbols and unknown relocation
types before execution through `ctypes`.

The comparisons cover all TOP values, empty/nonempty tag patterns, tag
reclassification, 160 deterministic random control/status/tag/pointer images,
the mask side effect, and retained physical contents after pop/reinitialization.
The oracle's x64-mode instruction uses the same 28-byte field layout; it does
not validate protected-mode segment fault behavior. Non-Windows/non-x64 systems
skip the hardware tests. `TF_TEST_CLANG` may select a compiler; otherwise PATH
and configured Android SDK NDKs are searched. Test compiler artifacts are kept
under ignored `work/tests/x87-semantics/`.
